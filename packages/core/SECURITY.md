# @p2prpc/core security

Production nodes must configure `SessionSecurity`; there is no anonymous default. A locator or Iroh peer ID is not application authorization. Prefer short-lived OAuth access tokens verified by `createOidcSessionSecurity` with exact issuer/audience/algorithm/JWKS checks, mandatory operation scopes, a one-hour default/24-hour maximum age, and default `cnf.jkt` binding to the Iroh endpoint key. The shared-secret helper is intended for securely provisioned workload groups: supply at least 32 bytes of cryptographically random material (length validation cannot measure entropy). It denies every operation unless its explicit `authorize` callback grants it; use `authorize: () => true` only when every secret holder is intentionally authorized for the complete application surface. `dangerouslyAllowInsecureSessions()` is only for isolated tests.

Signed tickets, DNS/PKARR, and LAN mDNS are explicit locator choices; they provide route bootstrap, not application trust or authorization. DNS and mDNS are disabled unless enabled in `iroh.discovery`, and selecting mDNS starts an explicit browse of its configured service. Enabling DNS installs an endpoint-wide native fallback that can supplement ticket or mDNS hints. Every outbound `connect()` also requires an independently trusted expected endpoint ID and exact canonical principal matcher. Route/connection mismatch fails before credentials are requested, principal mismatch fails before the peer is installed or returned, and the frozen target remains required on reconnect. Never derive the expected endpoint or principal solely from an untrusted locator. Provision those expectations through a trusted directory or enrollment channel, use `preAuthorizePeer` for broader endpoint-key admission, and retain session authentication plus per-operation authorization.

Select relay behavior with `iroh.relay`: `{ mode: 'default' }`, `{ mode: 'custom', urls: [...] }`, or `{ mode: 'disabled' }`. Custom relays must be credential-free HTTPS origins and remain relay-assisted because Iroh may upgrade to a direct path. On a DNS-disabled endpoint, signed-ticket and mDNS candidates can be filtered before dial with `allowDirectAddress` and `allowRelayUrl`; enabling DNS plus either callback fails closed because the pinned wrapper cannot expose DNS-resolved candidates for application egress review. Without a callback, mDNS direct hints are limited to private/link-local/loopback ranges and default-network relay hints are rejected. Custom mode restricts relay hints to configured canonical origins before invoking the optional callback; disabled mode rejects all relay hints. In exact-pinned `@momics/iroh-http-node` 0.6.0, disabled relays also imply loopback-only networking, so this package does not claim production relay-less operation with that version.

RPC metadata and remote filenames are untrusted. File capabilities should remain peer- and, where applicable, issuer-aware principal-bound. Resolve authorized object IDs inside service-owned source roots and never pass caller-supplied paths to `fileSource()`. Received content should use a service-owned destination parent, be quarantined, and be scanned before use. The built-in destination performs whole-file verification before publication; a custom destination is a trusted adapter and must provide equivalent final digest verification, cancellation, and atomic commit behavior. Do not automatically break a destination lock after a crash. Long-lived subscriptions require application heartbeats within their I/O timeout.

Use distinct OAuth audiences and connection scopes per application/environment/trust domain. Non-idempotent mutations require durable application-level idempotency keyed by the verified principal and tenant, procedure, and caller-supplied key. Prefer `allowedPrincipals` for capabilities; `allowedSubjects` is deprecated, and `allowBearer: true` only permits endpoint-ID binding to be omitted.

`onSecurityEvent` is best-effort observability, not a durable audit log. Export it to a monitored durable sink. OIDC principal IDs are now hashed from issuer/subject/client; migrate security state keyed by the former readable IDs.

The repository-level `SECURITY.md` documents the full threat model, controls, operational requirements, residual native-transport limitations, migration notes, and private reporting guidance.
